# Argentina Monetary Deep Dive — Promise versus Delivery, 2023–2026

Replication repository for the working paper *Promise versus Delivery: The Fiscal
Anchoring of Argentina's Disinflation under Milei, 2023–2026*
([PDF](https://nikkhosravipour.com/assets/papers/dae618c21735d5da1bbfb0620c40a59c.pdf))
and the deep dive
[*Argentina's Monetary Report Card*](https://nikkhosravipour.com/post/argentinas-monetary-report-card-promise-versus-delivery-under-milei).

Section order follows the
[Social Science Data Editors template README](https://github.com/social-science-data-editors/template_README).

## Overview

Python ingests and cleans; R analyzes; outputs are Chart.js HTML widgets for the
site plus static PNG fallbacks and markdown/HTML regression tables. The pipeline
mirrors the Taylor-rule deep dive repo so the two projects read as one research
program. `make all` runs ingest through charts (see Instructions to Replicators
below); `run_all.R` alone reproduces every table and figure listed in the paper.

## Data Availability and Provenance Statements

**VINTAGE LOCKED 2026-06-13** at the May 2026 CPI print (`vintage_end:
2026-05-31` in `config/params.yaml`). No observation after that date enters the
panels, and the ingest scripts refuse to run while `vintage_locked: true`. Every
raw download is timestamped under `data-raw/{source}/{YYYY-MM-DD}/` and never
overwritten. All published estimates are recomputed on this locked panel only.

`data-raw/` is **gitignored** — none of the raw provider files ship in this
package. `data-raw/MANIFEST.sha256` records the sha256 of every raw file at the
locked vintage so a replicator who re-downloads from the URLs below can verify
they match what the published results were computed on.

All seven sources below are secondary data: none were generated by the authors.

### Statement about Rights

The data are drawn from public statistical APIs and public/semi-official web
endpoints of the Argentine central bank, the national statistics institute,
the national open-data portal, and financial media. No confidential, licensed,
or human-subjects data are used. No redistribution rights beyond linking to the
original source are claimed for any raw file (none are provided — see above).

remains subject to each provider's own terms; none of it is redistributed in

## Computational requirements

- R 4.3.3 — packages (see `R/00_setup.R`'s `packages` vector): `dplyr`, `zoo`,
  `lubridate`, `yaml`, `urca`, `lmtest`, `sandwich`, `strucchange`, `lpirfs`,
  `fixest`, `modelsummary`, `jsonlite`. The environment is pinned by
  `renv.lock` (`renv::restore(prompt = FALSE)` runs automatically from
  `R/00_setup.R`); **snapshot taken 2026-09-08; versions current on CRAN that
  day, not the 2026-06 analysis environment.** Exact package and R versions
  used to produce the `output/` artifacts are recorded verbatim in
  `output/session_info.txt` (written locally by the last block of `run_all.R`,
  `sessioninfo::session_info()`; not committed because it embeds local paths) — that file, not `renv.lock`, is the record
  of what actually ran. That file was produced by full `Rscript run_all.R`
  recomputes on the locked panel (2026-09-08, no re-ingest, run three times to
  test reproducibility). Findings: the gitignored intermediate
  `output/data/*.rds` caches (explicitly marked "regenerable" in `.gitignore`)
  reproduced **byte-for-byte identically across all three runs** — the
  computed numbers are stable. The committed `output/figures/*.png` and
  `output/tables/table2_money_demand.{md,html}` did *not* reproduce
  byte-for-byte run-to-run; pixel-diffing the PNGs (`Pillow`/`numpy`) showed
  every differing pixel confined to anti-aliased text glyphs (titles, axis
  ticks, legend labels) with the plotted data region itself pixel-identical,
  and diffing the table showed only pandoc grid-table border/padding width
  shifting by one column-character with every numeric cell value unchanged.
  Root cause is text/table rendering non-determinism in the plotting and
  `modelsummary` calls (`R/01_descriptives.R` onward), not the analysis —
  outside this item's scope to fix. No published number changed on any
  recompute; only cosmetic rendering bytes did. The committed `output/`
  artifacts in this repo are therefore the versions as originally rendered,
  restored after each verification recompute; this pipeline is not fully
  bit-reproducible for figure/table rendering, and no further recompute
  happens without sign-off.
- `lpirfs` is optional: it provides only a full-sample packaged cross-check
  of the pass-through local projections (`R/04_passthrough.R`), not the
  primary estimates. On the analysis host it was not installed, so that
  packaged cross-check was skipped and `output/passthrough_lpirfs.rds` was
  never written by this environment; the reported pass-through estimates are
  the manual local projections in `R/04_passthrough.R` (transparent, NW
  errors), which do not depend on `lpirfs`. `lpirfs` is deliberately
  **excluded** from `renv.lock` for the same reason — `R/00_setup.R` loads
  the `packages` vector defensively and warns rather than errors when a
  package (only ever `lpirfs`) is missing. If a replicator installs `lpirfs`
  independently, note that the packaged cross-check output is still absent
  from this package — the committed `output/` artifacts are not re-generated
  for it.
- Python 3.12 — packages pinned in `python/requirements.txt`: `requests`,
  `pandas`, `openpyxl`, `xlrd`, `certifi`, `pyyaml`, `pyarrow`.
- Runtime: `make ingest` is network-bound (BCRA/INDEC/REM/Ámbito downloads,
  seconds to low minutes per source); `make analysis` (`run_all.R`, R modules
  01–11) runs single-threaded in well under 10 minutes on a standard laptop;
  `make charts` is seconds. No cluster or GPU is used.
- Memory/storage: under 2 GB RAM; `data-raw/` + `data/` + `output/` together
  are well under 100 MB.

### Controlled Randomness

The only randomization is the moving-block bootstrap in the event study
(`R/05_events.R`, `event_study.n_boot` = 2000 replications, `block_len` = 5
trading days). The seed is fixed at `config/params.yaml:boot_seed` (`20260531`
— set equal to `vintage_end`, so it is reproducible and not a timestamp). No
other module uses a pseudo-random generator.

## Instructions to Replicators

```sh
make deps        # python venv + pip install, R package install
make bcra-cert   # one-time: build the BCRA TLS chain bundle (see below)
make ingest      # run all python ingest scripts -> data/ (blocked while vintage is locked)
make panel       # build data/panel_monthly.csv + data/panel_daily.csv
make analysis    # R modules 01-11 (run_all.R)
make charts      # R module 09 -> output/widgets/*.html + output/figures/*.png
make all         # everything above except deps and bcra-cert
```

### BCRA TLS certificate workaround

The BCRA API server (`api.bcra.gob.ar`) serves an incomplete certificate chain.
Verification is **not** disabled; instead `make bcra-cert` exports the full
chain presented by the server via `openssl s_client -showcerts` into
`config/bcra_chain.pem`, which the ingest scripts use as the CA bundle
(override with the `BCRA_CA_BUNDLE` env var). If the certificate ever rotates,
re-run `make bcra-cert`.

### Where things can drift (check on first run)

- **BCRA series IDs** are never hardcoded. `ingest_bcra.py` queries the
  variable catalog and matches descriptions against the regexes in
  `config/series_ids.yaml`. If a regex matches zero or multiple variables the
  script dumps the catalog to `data-raw/bcra/` and tells you which regex to
  fix.
- **File URLs** (INDEC cuadros, REM database, ITCRM) live in
  `config/urls.yaml`. INDEC and REM filenames change; the scripts scrape the
  landing pages as a fallback, but if both fail, paste the current link into
  `config/urls.yaml`.
- **Ámbito endpoints** (EMBI, MEP, CCL) are semi-official and may change
  shape.
- **Comparators**: monthly CPI for Israel 1985 and Brazil 1994 come from
  FRED's keyless CSV endpoint and the BCB SGS API respectively, not IMF IFS —
  the IFS SDMX API was migrated in 2025 and the legacy endpoint retired. Same
  numbers, stable access, no key needed.

### Event registry

`config/events.csv`. Dates marked `VERIFY` must be confirmed against Boletín
Oficial entries, BCRA "Comunicación A" communiqués, or IMF press releases
during ingest, and the primary-source citation recorded in the `source`
column. Every date in the published piece must trace to a primary document.

### INDEC division weights

`config/indec_division_weights.csv` holds the national IPC division weights
(base December 2016). **Verify against the INDEC IPC methodology document
before publication** — the dispersion measure renormalizes them to sum to
one, so small errors do not propagate, but the cited values must be exact.
